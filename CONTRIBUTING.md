# Contributing to CyberProtocol

Thank you for helping build a neutral, open standard for AI trust. CyberProtocol
is a public good: it competes with no existing standard, it unifies them.

## Ways to contribute

- **Specification**: review the text in [`specs/`](specs/), propose clarifications, or raise gaps.
- **Reference implementation**: build or improve the verifier and issuer in [`reference/`](reference/).
- **Examples & schemas**: add sample DIDs, seals, and compliance metadata in [`examples/`](examples/).
- **Policy & compliance**: help map the compliance vocabulary to EU AI Act, NIST AI RMF, and ISO/IEC 42001.
- **Documentation**: improve guides and integration notes in [`docs/`](docs/).

## Process

1. **Open an issue** first for anything non-trivial, so the approach can be discussed in the open.
2. **Fork** the repository and create a descriptive feature branch.
3. **Make your change.** Keep specification changes and code changes in separate pull requests where possible.
4. **Open a pull request** that explains *what* changed and *why*. Link the issue it resolves.

## Principles

- **Neutral.** No proposal should privilege one nation, company, or bloc.
- **Interoperable.** Prefer reusing mature standards (W3C, ISO, NIST) over inventing new mechanisms.
- **Privacy-first.** Compliance must be provable without forcing disclosure of confidential data.
- **Plain language.** Write for implementers in many jurisdictions; avoid idioms and ambiguity.

Be respectful, assume good faith, and keep discussion standards-first. Harassment or
discrimination of any kind is not tolerated.
